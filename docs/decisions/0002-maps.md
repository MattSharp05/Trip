# 0002 — Map rendering

**Status.** Final pending Matthew's pick on TR-5 (Decision section, at the Plan checkpoint). The
recommendation below is the default. If he picks otherwise, this ADR flips to the other option and
TR-13 follows it.

**Context.** The Plan screen's map is the product's centrepiece: dark, photo pins, a day's route,
fly-to on selection, and a cinematic globe with great-circle flight arcs. In Expo Go the options are
`react-native-maps` (Apple Maps; native; little styling) or MapLibre GL JS inside
`react-native-webview` (full styling, globe projection, free OpenFreeMap tiles; web gestures).
The TR-5 spike built both (`/dev/map-spike`: tabs A, B and Globe, with the same Vegas day).

**What the spike found.**

| | A: Apple Maps (`react-native-maps`) | B: MapLibre GL JS in a WebView |
|---|---|---|
| Look vs mockup | Apple's dark `mutedStandard`, POIs hidden. Very close to the mockup's map, Apple's 3D landmarks in Vegas. Colours can't be changed. | Our own dark style from tokens (`src/theme/map.ts`): exactly our palette, 3D extruded buildings, few labels. Flatter, less detail than Apple. |
| Gestures | Native MapKit: pinch, pan, rotate, two-finger tilt, inertia as in Apple Maps. | Web gestures in WKWebView: all work, inertia and pinch feel slightly different from native. |
| Photo pins | RN views as markers (real UIViews on iOS). | DOM markers; 30 pins fine in Chromium. |
| Cold start | Native view, map ready on mount (`onMapReady`). | WebView boot + MapLibre (about 800 KB, CDN in the spike) + tiles. Chromium, iPhone profile, no cache: 1.8–3.9 s to first idle map (4 or 30 pins, no difference). |
| Memory | Not measurable from JS in Expo Go. | MapLibre JS heap 9–13 MB in Chromium, plus the WebView process. |
| Globe | `hybridFlyover` zoomed out is a real satellite globe (like the mockup), geodesic arc as a polyline; the plane is a marker moved from JS (about 30 updates a second). | Globe projection with our dark style and atmosphere, arc and plane animated in the page (smooth `requestAnimationFrame`). |
| Cost, keys | None. | None (OpenFreeMap fair use). |
| Phase B | Same code. | Can move to native MapLibre (`maplibre-react-native`) in a dev build. |

Numbers for B come from headless Chromium with software WebGL (the cloud session has no iPhone), so
they're an upper bound for load and say nothing about frame rate. The spike screen shows "Ready in
… s" for each tab and "fps last move" for MapLibre so the phone gives the real numbers.

**Decision (recommended).** **A: Apple Maps** for the city map. Native gestures and instant start
matter more on the main screen than exact colours, and Apple's dark map already reads like the
mockup. For the flight globe, Apple's flyover globe if it feels right on the phone (one map
technology, no WebView); otherwise the MapLibre globe in a WebView.

**Consequences.**
- No API keys or costs either way.
- The map component sits behind a small interface (`TripMap`: pins, route, selected id, fitTo,
  flyTo; the spike's `SpikeMapHandle` is its first draft) so the choice can change without touching
  Plan.
- If B is chosen: bundle MapLibre into the app (an inline asset, not a CDN) for offline and faster
  start, and pin v5 (the last UMD build; v6 is ES modules only with a separate worker that a WebView
  page can't load cross-origin).
- TR-13 builds the production map on the chosen renderer and deletes `src/features/map-spike/` and
  `app/dev/map-spike.tsx`.
